## What is interesting

- `@pm`/`@pmFromFile` is a **phrase** match: fast, no regex, list kept in a
  `.data` file next to the rules. Changing the list changes the rule.
- `t:normalizePathWin` turns `\` into `/` and resolves `./` and `../`
  before matching, so Windows-style paths match the same list.
- Some rules appear twice in one transaction (930100, 930110): CRS rules can
  match the same variable more than once (`multiMatch` or several targets).

## One-variable experiments (`file` parameter)

| `passwd` | no match | allowed | 0 |

The traversal (`../`) is caught by 930100/930110; the **target file name** is
caught by 930120. They are independent signals that add up.

## Possible false-positive causes

Documentation or support text that names system files ("my `/etc/hosts` is wrong").

## Safest tuning point

Argument-scoped exclusion on a documentation/support field only.
