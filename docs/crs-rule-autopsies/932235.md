## The family (from the comments above the rule)

932230 handles prefix + 2–3 letter commands. **932235 handles prefix + longer known commands.** 932250/932260 do the same without a prefix. 932236–932239 are stricter siblings at PL2/PL3. Raising the paranoia level adds siblings. It doesn't touch 932235.

## One variable at a time (JSON `comment`, route `/api/Complaints/`)

| `comment` | 932235 | Matched data |
| --- | --- | --- |
| `link ?utm_source=mail in the footer` | **match** | `=mail ` |
| `link ?utm_source=mail` (end of text) | no match | nothing after `mail`, so no delimiter |
| `link ?utm_source=email in the footer` | no match | `email` isn't a command |
| `?utm_source=mail&x=1` | **match** | `=mail&` |
| `please mail me` | no match | no prefix |
| `x;mail me` / `x; mail me` | **match** | `;mail ` / `; mail ` |
| `x=mailx y` | **match** | `=mailx ` (mailx is on the list too) |

All three pieces have to be there: prefix, command, delimiter. A pasted URL hands over the prefix (`=`) and the delimiter (space or `&`) by pure accident.

## What triggers false positives

Pasted URLs whose parameter values happen to be command names: `=mail`, `=find`, `=more`, `=time`. And free text after a `;`.

## Safest place to tune

Runtime exclusion **1010**. Only rule 932235, only `ARGS:comment`, only `POST /api/Feedbacks`. No threshold change, no `SecRuleRemoveById`.
