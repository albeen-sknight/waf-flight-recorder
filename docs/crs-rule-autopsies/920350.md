| Field | Value |
| --- | --- |

| File / line | `REQUEST-920-PROTOCOL-ENFORCEMENT.conf`, line 756 |
| Category | `attack-protocol`, paranoia level 1 |
| Phase | 1 (request headers) |
| Targets | `REQUEST_HEADERS:Host` — one header |
| Transformations | `t:none` |
| Operator | `@rx (?:^([\d.]+|\[[\da-f:]+\]|[\da-f:]+)(:[\d]+)?$)` — IPv4, bracketed IPv6 or bare IPv6, optional port, anchored |
| Actions of note | `block`, severity **WARNING** → `+%{tx.warning_anomaly_score}` = 3 |
| Triggering request | SCORE-001 `GET /` with `Host: 127.0.0.1` (sample: [`phase1-numeric-host-allowed.json`](../../evidence/sanitized-samples/phase1-numeric-host-allowed.json)) |

| Matched data | `127.0.0.1:8080` |
| Score contribution | +3 |
| Final decision | **Allowed** — 3 < threshold 5 |

## Why it exists

Real browsers send a hostname. Requests addressed to a bare IP are typical of
scanners and bots sweeping IP ranges. It is a weak signal on its own, so CRS
gives it WARNING (3), not CRITICAL (5).

| `10.0.0.1.nip.io` | no match (not anchored-numeric) | 0 | allowed |

Combined with an empty User-Agent (920330, NOTICE = 2) the total is 5 and the
request is blocked (SCORE-004) — see the [anomaly-scoring experiment](../anomaly-scoring-experiment.md).

## Possible false-positive causes

Health checks, monitoring and the developer's own `curl http://127.0.0.1`.
This lab hit it immediately: the Docker health check would have logged it every
5 seconds — solved by exclusion 1000 (health route skips ModSecurity), and the
test runner sends `Host: localhost`.

## Safest tuning point

Exclude the monitoring route (as rule 1000 does), not the rule.

## Regression test

`SCORE-001` (match, score 3, allowed) and `SCORE-004` (3 + 2 = blocked).
