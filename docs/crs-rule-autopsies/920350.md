## Why it's there

Browsers send a hostname. Requests aimed at a bare IP usually come from scanners and bots sweeping address ranges. On its own that's a weak signal, so CRS gives it WARNING (3) instead of CRITICAL (5).

Pair it with an empty User Agent (920330, NOTICE, 2 points) and you're at 5. Blocked (SCORE-004). More in my [anomaly scoring experiment](../anomaly-scoring-experiment.md).

## What triggers false positives

Health checks. Monitoring. My own `curl http://127.0.0.1`. My lab tripped it on day one: the Docker health check would've logged it every 5 seconds. I fixed that with exclusion 1000, which skips ModSecurity on the health route, and my test runner sends `Host: localhost`.

## Where I'd tune it

Exclude the monitoring route, like my rule 1000 does. Not the rule.

## Regression test

`SCORE-001` (match, score 3, allowed) and `SCORE-004` (3 + 2, blocked).
