# FP-002 — Juice Shop's own PUT/DELETE requests blocked by CRS 911100

| | |
| --- | --- |
| Status | Fixed (configuration), regression-tested |
| Rule | CRS 911100 — Method is not allowed by policy, CRITICAL |
| Fix | `tx.allowed_methods` (rule 900200) in `modsecurity/crs-setup.conf` |
| Scenarios | NRM-003 (PUT), NRM-004 (DELETE), MTH-001/002 (WebDAV still refused) |

## Evidence before

With CRS defaults (`tx.allowed_methods=GET HEAD POST OPTIONS`):

```
PUT    /api/BasketItems/1  {"quantity": 2}   BLOCKED 403  911100 + 949110  score 5
DELETE /api/BasketItems/1                    BLOCKED 403  911100 + 949110  score 5
```

Samples: [`fp002-before-put-blocked-911100.json`](../../evidence/sanitized-samples/fp002-before-put-blocked-911100.json),
[`fp002-before-delete-blocked-911100.json`](../../evidence/sanitized-samples/fp002-before-delete-blocked-911100.json).

Changing a basket quantity and removing an item are core shop functions.

## Why it is not an exclusion

911100 is doing exactly what it is configured to do. The configuration did not
describe this application. CRS exposes the method list as a setting, so the fix
is the setting:

```apache
setvar:'tx.allowed_methods=GET HEAD POST OPTIONS PUT PATCH DELETE'
```

## Evidence after

`PUT /api/BasketItems/1` → allowed, no rule matched
([`fp002-after-put-allowed.json`](../../evidence/sanitized-samples/fp002-after-put-allowed.json)).

## Trade-off and compensating control

PUT/PATCH/DELETE are now allowed on every route. Two local rules narrow that back:

- **100010** refuses WebDAV methods (PROPFIND, MKCOL, …) with 405.
- **100060** refuses `DELETE /api/Feedbacks/*` specifically (a Juice Shop challenge).

## Note on `@within`

911100 uses `!@within %{tx.allowed_methods}` — a substring test. With PATCH in
the list, a method named `PAT` would also pass. Local rule 100010 uses an
anchored `@rx` for this reason (see `custom-rules/110-method-policy.conf`).
